# IC-SHM 2026 项目 2：官方要求要点

> 更新日期：2026-07-30。  
> 信息来源：*The 4th International Project Competition for SHM_2026* 比赛说明 PDF，以及主办方已提供的两组项目 2 邮件澄清。  
> 本页只记录已确认的比赛事实和直接执行含义；完整背景、公式和团队建议见[比赛说明与执行指南](../../项目2比赛说明与执行指南.md)。最终评测协议和脚本发布后，以其为准。

## 一句话任务定义

基于同一座桥梁的已发布多视角图像，建立一个可渲染的语义三维场景。盲测时，程序接收主办方指定的隐藏测试相机参数，必须在**不读取测试 RGB 或语义标签**的前提下，输出该视角的 RGB 渲染图和五类语义图。

因此，这是一项单场景的新视角重建与三维语义渲染任务，不是只做二维分割，也不是跨桥梁泛化任务。

## 已确认的事实

### 数据与标签

| 项目 | 已确认内容 |
|---|---|
| 标注数据 | 300 张 UAV 多视角 RGB 图像和 300 个一一对应的 LabelMe JSON 文件 |
| 无标注数据 | 100 张同场景多视角 RGB 图像，可用于 RGB 重建、几何或半监督方案 |
| 相机 | 已发布图像均有 COLMAP 文本格式参数；当前数据校验结果为 400 个位姿、`SIMPLE_RADIAL`、1320×989 |
| 类别 | `0 background`、`1 deck`、`2 stay_cable`、`3 tower`、`4 foundation` |
| 点云 | 未提供 `points3D.txt` 是有意安排；参赛队伍自行三角化、重跑 COLMAP 或选择其他初始化方式 |

`stay_cable` 是 Class ID 2 的唯一正式名称；旧资料中的 `main cable` 不得再作为正式输出标签。

### 相机与坐标系

- `cameras.txt` 给出相机模型、宽高、内参和畸变参数；`images.txt` 给出图像关联和位姿；另有 `rigs.txt`、`frames.txt`。
- `images.txt` 的外参是 COLMAP 的世界到相机变换（`CAMERA_FROM_WORLD`），不是 camera-to-world；相机中心应按 `C = -Rᵀt` 计算。
- 盲测相机使用官方 COLMAP 参考坐标系。允许优化或重估训练位姿，但提交程序必须把官方测试相机正确转换至模型坐标系。
- 若模型使用不同坐标系，必须与 checkpoint 或配置一同保存、加载并应用 Sim(3)（尺度、旋转、平移）对齐。
- 畸变参数是输入的一部分。训练与渲染必须有一致的畸变处理策略；RGB 和语义重采样规则不同，语义不得用双线性插值。

### 盲测输出

- 测试集与已发布数据来自同一桥梁和场景，但测试 RGB 和 GT 语义保持隐藏。
- 程序会收到测试相机所需的信息，包括内参、外参、模型、宽度和高度。
- 当前发布图像是 1320×989，测试输出预计相同，除非最终协议另有规定；实现应从相机输入读取宽高，不能硬编码。
- 必须同时输出 RGB 和语义。当前推荐语义格式是单通道 PNG，像素值为官方类别 ID 0–4；最终命名、目录和格式以官方协议为准。

## 评分与提交

项目 2 的模型准确度由两部分组成：

```text
Accuracy Score = 0.50 × Visual Fidelity Score + 0.50 × Semantic mIoU Score
```

视觉保真使用 PSNR、SSIM、LPIPS；语义准确度使用 mIoU。比赛总分则为：

```text
Final Score = 0.35 × Accuracy Score + 0.25 × Video Score + 0.40 × Paper Score
```

提交包需要有注释的 Python 代码、README、必要的数据访问方式、checkpoint、配置和渲染脚本，以及 10 分钟英文汇报视频、PPT 和 10–15 页英文论文。Docker、Conda 和自定义 C++/CUDA 扩展可以使用，但必须清楚且可复现。代码不能复现时，官方 FAQ 规定 Accuracy Score 为 0。

提交截止日期为 **2026-09-30**；主办方的复现与评测阶段为 **2026-10-15**。

## 尚待官方发布，必须配置化处理

- LPIPS 的 backbone、权重、预处理和值域；
- PSNR、SSIM、LPIPS 的归一化与 Visual Fidelity Score 合成方式；
- RGB 是否裁剪、遮罩、忽略区域或背景处理；
- mIoU 是否包含背景、无类别图像和 ignored region 的处理方式；
- 测试相机样例、最终命令行接口、输出目录、文件命名和格式检查；
- 执行环境、GPU/时间/显存限制和 checkpoint 大小限制。

这些未发布项不能被写死为“官方规则”，也不能据此过度优化某个本地总分。

## 对本项目的不可违反约束

1. 渲染入口必须接收外部官方测试相机，并正确解释 `CAMERA_FROM_WORLD`。
2. 最终语义必须来自三维表示或不依赖测试图像的渲染路径。
3. 如果 RGB 骨干冻结，后续语义训练不得改变其几何、颜色或 opacity；应检查 RGB 像素一致性。
4. 所有本地模型选择和创新结论使用空间隔离的未见视角，不能用相邻帧随机划分代替。
5. 数据、模型、训练输出、日志和个人机器路径不进入 Git；数据版本通过 manifest 指纹验证。
6. 提交适配层、坐标对齐、畸变处理、格式检查和干净环境复现与模型指标同等重要。

## 当前仓库的执行定位

本仓库已经完成数据 manifest 验证，并规划了以下顺序：先在一致的数据、相机、畸变策略和空间折下公平比较 Standard 3DGS、Mip-Splatting、Scaffold-GS；冻结能通过外部相机与语义冒烟测试的 RGB 骨干；再进行五类语义基线、可见性感知监督、跨视角冲突统计和受限的视角条件语义残差实验。

这条路线是团队设计，不是官方指定算法；只有通过预注册的未见视角、三种子和 RGB 保持不变等门槛后，才能将其中的创新写成已验证结论。
