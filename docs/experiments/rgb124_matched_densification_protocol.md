# RGB124 预算匹配增密短程对照草案

2026-09-15：RGB123只读诊断支持进一步检验，不是增密有效性结论。拟议 `RGB-124-MATCHED-DENSIFICATION-PF`，尚未训练；沿用用户“不自动重训”边界。以下为待实现、待执行协议，不冒充已通过工程验证。

父RGB120全400，seed0、官方PINHOLE、初始化与数据manifest/split不变。从同一真实7k检查点及其优化器状态建立两个独立候选副本。两臂各500更新（7k→7.5k），同一预生成相机次序、学习率时间点、RGB损失与随机状态；终点唯一，不选checkpoint、不重复seed，不自动延伸30k。

唯一比较变量是增密候选的排序信号：控制保留原signed二维梯度L2；候选使用每像素先分别取绝对值、分别累加x/y后取L2。RGB123仅导出了绝对梯度L1合计，不能直接把它命名为完整AbsGS实现：执行前必须增加独立x/y绝对分量，确认native梯度和forward恒等及单像素oracle通过，不改变真实RGB反向传播。

两臂共同采用固定新增预算和统一候选选取实现，避免高梯度数值直接制造更多点：每100更新一次，五次各最多128个新anchor，总上限640。在相同原生栅格层级与offset资格规则下，按分数聚合/排序去重格子，tie按确定性格子坐标；新增anchor的初始化规则完全相同。逐次两臂取共同可用数量min(128,控制可用格数,候选可用格数)，逐层配额同步，保存选中格子与实际点数。不得在某臂不足时增加层级或扩大空间。短程中两臂共同关闭删除，严格匹配实际新增anchor数；因此这两个控制都是对原生配方有共同改动的研究对照，不能把它们称为未改RGB120续训，也不能把与旧30k的差异单独归因梯度排序。

执行前先做零更新身份复现和预算选择单元核验；同一候选列表/同一分数输入必须逐项一致，确保差异来自排序信号。两臂模型、优化器和数据访问隔离；保存source/config/point-count/seed绑定与所有失败。RGB130/131及SEM371/372另一主线优先级不被本草案覆盖；未来启动时使用空闲GPU窗口。

终点比较：全部400照片的RGB误差分布、固定159/160/161原ROI、049/241反例、真实stay_cable和deck照片边界、8插值相机；区域掩膜只用于评价，不输入排序，不以标签保护阻止候选训练。保存照片/两臂/差分原生图，主要拉丝必须视觉核查；结构像素颜色变化与结构损伤分清。训练内评分不是泛化。短程无收益就保留负结果并停止这次配方，不扫增密门/配额/步数；即使收益为正，也只支持新的独立完整验证，不自动推广正式RGB或语义。

预计计算约2–5分钟GPU（未实测，含两臂1000更新和全400终点评价；模型构建/编译额外），新增约0.5–1GiB，原模型保留。确切时间、空间须以实现后的工程探针为准。本草案不授权全量重训。
