# SEM-090-CABLE-NETWORK-DIAG：训练侧三类桥索线网诊断

## 状态

已完成8-view训练侧GPU预检，因视觉门失败而停止；219-view full 和74-view均未运行。

## 假设

SEM-080 的失败不是“删除背景”这个目标错误，而是把所有正常索线压缩为单一 tower→deck 关系。
本诊断只改变这个后处理谓词：从冻结 SEM-001 概率中同时保留三种 Hough 线模板：主缆
（tower-top↔tower-top/画面边界）、吊索（deck↔已保留主缆）和斜拉索（tower↔deck）。只有不属于
任一模板的 raw `stay_cable` 像素才移至background。

这仍是训练侧诊断：只读取219个训练视角，按既有hash parity分别报告 calibration/check；标签仅在
无标签谓词完成后用于度量。74-view、无标注、隐藏输入和外部相机一律不打开。规则参数固定，
不在本实验内调参或选择候选。

若样例仍删去任一正常索线家族，或check的官方质量权衡无效，即刻drop并保持 SEM-001 回退。

## 预检结果与止损

预检在8个授权训练视角（5 calibration / 3 check）完成，checkpoint逐位重载和RGB=0均通过，
且没有读取验证、无标注或隐藏输入。它检测到358条主缆、168条吊索和736条斜拉索候选，说明
三类模板在工程上可执行。

但 `training_cable_network_triptych/001.png` 显示：相较SEM-080，更多正常主缆和吊索得到保留，
但左侧江水的大块黄色语义仍被保留。根因是主缆的 `tower-top→image-boundary` 模板会接纳江面上
起于桥塔附近并延伸至画面边缘的稠密错误Hough线；从错误的 `stay_cable` 图自身提线再用其连接
关系筛选，无法形成独立的真假证据。

8-view的check只是预检，不作为质量指标；但视觉条件已经失败，故不运行219-view full、不打开74-view、
不调本规则参数，也不生成外部相机或视频。`SEM-001` 保持唯一回退。下一步若继续，必须使用独立于
raw语义黄图的细线证据（例如冻结渲染RGB的边缘/重投影一致性）来支持线网，而非继续扩大Hough连接模板。
