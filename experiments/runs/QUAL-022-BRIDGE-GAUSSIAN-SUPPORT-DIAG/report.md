# QUAL-022 RGB170桥梁Gaussian支撑诊断

状态：已完成只读诊断。父模型为RGB170 50k，985,530个Gaussian；模型、相机、标签和旧输出均未修改。诊断覆盖全部300张有桥梁标签的视角，另列159--160、235--245、385--392，并对385--392真实照片中的线结构单独取样。标签只用于二维结构区、环带和评价定位；三维证据来自现有Gaussian中心、官方相机投影、真实照片局部切线和跨视角贡献。

## 证据

- 共执行1,208个“视角×结构”原生贡献追踪作业，保存97,474条贡献者记录；耗时139.08秒，峰值reserved 6,938MiB。结果为`outputs/quality/QUAL-022/diagnostic-r1/result.json`，SHA256为`67ab78c8c912e80ea011d746e4615e6f02928d79c9bffbfb7c3df032872623ff`。
- `stay_cable`前48贡献者椭圆覆盖中位97.4166%，照片可见索像素支持中位75.6216%。因此主要问题不是“完全没有Gaussian投影支撑”。
- 索区真实型贡献者只占22.7431%，伪影型占14.4653%，其余62.7917%为结构/背景责任不清的混合项。真实型长/短半轴中位137.36/57.11px，伪影型为365.30/142.60px；后者opacity中位0.28913反而高于真实型0.18474，跨视角出现中位7次与6次相近。低opacity或单视角支撑不是主导解释。
- 索区混合项方向误差中位57.28°。真实型方向误差中位16.53°，伪影型38.90°；支持“已有中心附近的尺度/方向/职责错误”，而非单纯容量不足。
- deck真实型占73.1667%，但伪影型投影长/短半轴中位189.06/87.44px，显著宽于真实型65.10/15.07px。tower真实型占74.8630%，伪影型163.43/78.84px，也显著宽于真实型67.08/7.08px。
- 385--392照片线取样更差：真实型仅33.5938%，伪影型41.9271%；伪影opacity中位0.46758高于真实型0.29134，长/短半轴123.49/32.72px高于真实型98.60/14.42px，方向误差37.31°对13.36°。这解释了断索、淡化、灰带和背景混合可同时出现。
- 159--160索区真实型/伪影型约32.29%/7.29%；235--245约22.92%/18.75%。根因并非只存在于385--392，也不能由少数好例替代全300判断。

## 结论与分支选择

主因是已有桥梁Gaussian的投影尺度过宽、方向与真实索/桥面切线不一致，且同一Gaussian在结构区和邻近背景承担混合责任。部分真实索仍缺少足够高对比支持，但“完全无支撑”、统一低opacity和只靠单视角的解释均与全300统计不符。

因此选择分支B，不选择A或C：不从标签凭空三角化新结构，不提高全局opacity，也不改采样/损失。RGB171只在一次原生LAS事件中，对同时满足真实照片梯度、官方相机、至少三视角切线一致性、结构/环带密度且本来已被原生LAS选中的桥梁父点，沿求解的局部三维切线布置子点并把横向尺度乘0.5。重复平行索不做跨索线匹配；弯曲主缆不被强制拟合为一条全局直线。
